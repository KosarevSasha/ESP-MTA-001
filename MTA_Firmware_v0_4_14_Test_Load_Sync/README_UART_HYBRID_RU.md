# UART Hybrid v0.4.14-DIAG (экспериментальная ветка)

База: **без изменений финансовой логики v0.4.13**. Этот файл добавлен отдельно; рабочая исходная ветка не изменена.

## Что изменено
- `PaymentManager.h/.cpp`: переключаемый режим обработки фонового RX.
  - `NORMAL` — штатный режим v0.4.13: весь поток идёт в парсер.
  - `DISCARD_IDLE` — входящие байты отбрасываются **только** пока `PaymentManager::State::IDLE`, нет ожидаемого ACK и не выполняется диагностика.
  - При настоящем платеже вся последовательность проходит через штатный парсер, без фильтрации `FF`, `00` и без вмешательства в финансовые данные.
- Диагностика `ShowPicture` из этого же `PaymentManager` без VendRequest/ReadCard, двигателя, записи NVS или продаж.
- Окно RX-счётчиков `FF`, `ZERO`, `OTHER`, `discardedIdle` по запросу.
- Защита от запуска платежа во время диагностической команды.
- Состояние по умолчанию **NORMAL** после каждой перезагрузки (экспериментальный режим не сохраняется).

## Команды USB Serial Monitor 115200
- `Q` — штатная диагностика оплаты (без изменений).
- `P` — штатные датчики (без изменений).
- `W` — вывести/обнулить счётчики RX с предыдущего W/запуска.
- `V` — переключить `NORMAL` ↔ `DISCARD_IDLE`. Только с открытой сервисной дверью, остановленным мотором, вне сессии.
- `H` — послать ShowPicture index=2 через PaymentManager (как "Выберите товар").
- `J` — послать ShowPicture index=1 через PaymentManager.
- `X` — **старая** ручная процедура разблокировки только по ранее установленным правилам. Самостоятельно не выполнять до проверки NVS и финансового исхода.
- `H/J` доступны только с открытой сервисной дверью, выключенным мотором и без платёжной сессии. Ответы: `DIAG_ACK_OK` или `DIAG_ACK_TIMEOUT` (3 сек). Команды не меняют NVS и не инициируют оплату.

## Последовательность испытания
1. Сохранить старую рабочую папку v0.4.13. Заменить **вместе** три файла: .ino, PaymentManager.cpp, PaymentManager.h. Остальные файлы конфигурации (включая локальные `mta_secrets.h` и `mta_tls_ca.h`) оставить прежними.
2. Для загрузки ESP32 через USB не подавать одновременно штатные +5V от ПРП. UART TX Vendista → GPIO39 **только через согласование уровней**, общая земля обязательно.
3. При открытой дверце убедиться в состоянии по `Q`. В случае ранее зарегистрированного `NVSphase=1` не делать повторных реальных попыток; проверить, что это были лишь тесты без оплаты. Диагностические `H/J` не снимают блокировку.
4. **NORMAL**: `W` (исходное окно) → `H`, затем `J`, затем `W`. Сохранить ответы.
5. Открытая дверца: `V` → увидеть `DISCARD_IDLE`. Повторить `W`, `H`, `J`, `W`.
6. После сравнения при необходимости `V` обратно в `NORMAL`. Перед реальными транзакциями использовать только после полноценной проверки безопасных состояний и NVS.
7. Если есть `DIAG_ACK_TIMEOUT`, не запускать полноценную оплату. Предъявлять карту или сканировать QR во время диагностики нельзя.

## Ограничения
- Очистка **не** фильтрует никакие байты во время активной платежной сессии: иначе можно разрушить допустимые двоичные payload.
- Успешная диагностика H/J не доказывает исправность полного платёжного сценария или физической формы сигнала.
- `uart_.flush()` вызывается только в диагностической команде H/J. Штатная отправка и таймеры v0.4.13 не менялись, чтобы сравнение было чистым.
- Предупреждение `gpio_pullup_en` на GPIO39 по-прежнему может появляться; это отдельная тема аппаратного уровня, не часть этой модификации.
- Исходники **не компилировались на реальной ESP32 в этой среде**. Первый этап — локальная компиляция Arduino IDE и не платёжные тесты.
