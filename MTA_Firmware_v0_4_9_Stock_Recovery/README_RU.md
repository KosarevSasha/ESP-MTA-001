# WANT!PAY!TAKE! — ESP32 v0.4.9 Stock Recovery (экспериментальная)

**Новая папка и новый .ino**: `MTA_Firmware_v0_4_9_Stock_Recovery/MTA_Firmware_v0_4_9_Stock_Recovery.ino`

Основа: протестированная v0.4.6 Event Delivery + HTTPS, согласованный `DOBRY_COLA_025`, локальная команда `D`. Предыдущие версии и ветка `main` не изменялись.

## Главное изменение

В пространстве NVS `mta-events` для каждой операции **LOAD +1** и **SALE -1** записывается единая запись `stockop` с намерением изменить остаток (предыдущее/новое значение, sequence, тип события). Затем записывается событие FIFO, далее остаток, и после успеха удаляется `stockop`. При следующем запуске:
- если намерение и соответствующее событие присутствуют, восстановление приводит остаток к целевому значению **один раз** и очищает намерение;
- если намерение записано, но событие даже не начало получать sequence, оно откатывается без изменения остатка;
- если метаданные неоднозначны, **операции блокируются**, а не производится произвольное исправление.

Это повышает устойчивость к выключению питания в ранее уязвимом промежутке записи, **но полное тестирование отказов (включая повреждение NVS или прерывание записи FIFO) ещё не пройдено**. Сообщение `RECOVERY BLOCKED` — причина остановить испытания и провести ручную сверку, а не очистить память.

## Защита существующего состояния

- Сохранённый ранее `MTA-001-E0000000002`, тип `LOAD`, количество 1, остаётся в NVS и ожидает отдельного согласованного этапа отправки.
- `MTA_ENABLE_EVENT_UPLOAD=false`: **после прошивки серверный остаток по-прежнему равен 0, ESP32 — 1**.
- `MTA_PRODUCT_ID="DOBRY_COLA_025"` для новых событий LOAD/SALE.
- Секреты в GitHub не хранятся: локально добавьте `mta_secrets.h` из рабочей HTTPS-версии с правильным ключом.
- PaymentManager, GPIO, механика и Caddy/VPS не изменялись.

## Проверка v0.4.9 (без проведения реальной продажи)

1. Скачайте тестовую ветку, откройте **новую** папку `MTA_Firmware_v0_4_9_Stock_Recovery`; проверьте, что имя папки совпадает с именем `.ino`. Перенесите `mta_secrets.h` локально.
2. Arduino IDE: **ESP32 Dev Module**, нужный COM-порт, Verify. **На момент подготовки версия не компилировалась на Arduino IDE и не испытывалась на физическом МТА.**
3. После успешной компиляции отдельно согласуйте Upload; отключите силовые исполнительные цепи, если это необходимо для безопасной перепрошивки. Serial Monitor 115200, No Line Ending.
4. Ожидаются `[MTA] WANT!PAY!TAKE! Firmware v0.4.9 Stock Recovery starting` и `Heartbeat ... HTTP=200`.
5. Команды `I` и `L`: ожидаем **stock=1**, один `LOAD` c `event_id=MTA-001-E0000000002`. Проверка `Q`: PM=IDLE, нет незавершённой оплаты.
6. По команде `D` **пока ничего не добавлять**, `Z/Y` не использовать, `Erase All Flash` не включать.
7. Проверка обычного EN/RESET: stock и LOAD должны остаться прежними.

## Важное ограничение

Это лабораторный прототип. В случае отказа записи NVS прошивка блокирует новые платёжные сессии; надпись панели `IDLE` сама по себе не доказывает готовность товарного учёта. Не эксплуатировать с реальными платежами до завершения тестов.
