MTA Firmware v0.4.6 — WI-FI + HEARTBEAT + EVENT DELIVERY (diagnostic)

База: v0.4.5 Heartbeat Only, успешно проверенная с сервером (HTTP=200),
с выдачей банки и оплатой в DEMO-режиме Vendista.

Что возвращено в v0.4.6:
- Исходная функция CommunicationManager v0.3.6: Wi-Fi + HTTP Heartbeat +
  POST /api/v1/device/events в отдельной FreeRTOS-задаче;
- NTP-синхронизация времени (configTime), необходимая для корректных
  created_at событий. Пока время не установлено, события остаются в NVS;
- Подтверждение сервером: только после принятого ответа событие удаляется
  из очереди NVS, иначе сохранено для повтора через 5 секунд;
- Отладочное сообщение об ожидании времени (максимум раз в 30 секунд).

Без изменений: PaymentManager.cpp/.h, GPIO, механические таймеры, StateManager,
платёжная логика, UART и его диагностика из предыдущих версий.

Установка:
1. Оставьте запущенным локальный сервер МТА (uv run server) на 192.168.1.106:8000.
2. Распакуйте архив в отдельную папку.
3. Скопируйте ТОЛЬКО свой mta_secrets.h из папки РАБОТАЮЩЕЙ v0.4.5,
   с уже исправленным MTA_DEVICE_KEY. Не делитесь ключом и Wi-Fi паролем.
4. Откройте основной .ino, скомпилируйте и загрузите в ESP32.
5. Serial Monitor: 115200. Проверьте Heartbeat state=IDLE HTTP=200 и Q.
6. Первая проверка (БЕЗ карты): ввод L показывает текущий NVS журнал.
   Не используйте T: TEST не отправляется автоматически и блокирует очередь,
   пока его явно не архивировать командой A.
7. DEMO-режим Vendista: одна продажа с выдачей банки.
8. Ожидаем:
   [MTA EVT] SAVED id=... type=SALE ...
   [MTA NET] Event id=... HTTP=200 confirmed=1
   [MTA EVT] CONFIRMED ... remaining=0
   [MTA NET] Heartbeat state=... HTTP=200
   [MTA PAY] PAYMENT_CYCLE_FINISHED ...
   Далее L, Q. Проверьте фактическую выдачу, сохранение SALE и отсутствие ERROR.

Если событие не принимается (401/422/и др.), НЕ очищайте журнал вручную,
пришлите журнал с [MTA NET] Event, [MTA EVT], [PM TRACE], а также L и Q.
Если Heartbeat=200, а событие не уходит, сначала проверьте NTP-время
и отсутствие TEST в голове журнала. Временные метки созданных без часов
событий приблизительны (время восстановления часов).

Замечания:
- Из-за сохранения программной финансовой неопределённости и диагностики
  только в DEMO-режиме, не использовать с реальными деньгами.
- Акт HTTP-доставки события не доказывает банковский перевод; отчёт Vendista
  подтверждается отдельно ACK.
- NVS-журнал не следует стирать/архивировать для устранения сетевой ошибки.
- При выключенном сервере события должны накапливаться и повторяться, но
  тест отказоустойчивости проведём отдельно.
