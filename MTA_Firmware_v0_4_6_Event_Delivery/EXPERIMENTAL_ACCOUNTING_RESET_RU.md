# Сброс экспериментального учёта МТА — тестовый этап

Ветка: `feature/firmware-v0.4.6-integration`. Изменения НЕ перенесены в `main`.

## Что изменено
В тестовую прошивку добавлена **двухшаговая команда Serial Monitor** для сброса исключительно локального экспериментального товарного учёта:
- `Z` (заглавная латинская) — вооружить сброс на 10 секунд;
- `Y` (заглавная латинская) — подтвердить сброс, пока он вооружён.
- Команды работают только при `IDLE`, отсутствии активной платёжной сессии, финансовой неопределённости и ошибок платёжного блокирования, при работающем журнале и `MTA_ENABLE_EVENT_UPLOAD=false`.
- Подтверждение логически освобождает сохранённые события из локальной очереди `mta-events` и сохраняет локальный остаток `stock=0`. Уникальный счётчик `seq` не обнуляется, чтобы не повторять ID событий. Другие NVS-пространства (включая PaymentManager) не затрагиваются.
- Исходные данные, удалённые из очереди, НЕ восстанавливаются этой функцией. Возможен частичный сброс при выключении питания; процедуру можно повторить после проверки безопасного состояния.
- Изменение состояния автомата `IDLE`/ `EMPTY` оставлено штатной машине состояний. Нулевой остаток блокирует запуск нового оплачиваемого сеанса.

## Порядок испытания
1. Скачайте свежую тестовую ветку в отдельную папку и добавьте локальный `mta_secrets.h` (не загружайте ключи в GitHub).
2. Compile/Verify в Arduino IDE, затем загрузка в ESP32 только при безопасном состоянии исполнительных устройств. **Компиляция и аппаратный тест этого изменения пока не подтверждены.**
3. Serial Monitor 115200: `L` (события), `I` (остаток), `Q` (платёжная диагностика).
4. Убедившись, что все данные тестовые и нет незавершённого платёжного сеанса, отправьте `Z`, затем отдельным вводом `Y` не позднее 10 секунд.
5. Проверьте сообщение `[MTA RESET] COMPLETE: stock=0, pending=0, preserved seq=...`; после этого повторите `L` и `I`.
6. Heartbeat должен продолжать возвращать `HTTP=200`. Отправка старых событий по-прежнему отключена.

## Сервер: отдельный этап
Серверная база SQLite не сбрасывается этим кодом. На VPS отдельно проверить актуальный `MTA_DB_PATH`, сделать резервную копию согласованным способом SQLite и только потом обнулить тестовые остатки/записи. Не удалять устройства, ключи и конфигурацию. Не обнулять глобальные идентификаторы событий без проверки идемпотентности.

## Перед тестами LOAD/SALE
Согласовать единый `product_id`: сервер сейчас показывает `DOBRY_COLA_025`, а код генерирует `WATER_05`. Добавление товара на сервер и в локальный счётчик следует тестировать отдельным контролируемым сценарием. Пока `MTA_ENABLE_EVENT_UPLOAD=false`.
